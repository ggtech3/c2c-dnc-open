# Project governance

The repository owner is the maintainer and decision maker. The maintainer controls project scope, review and release decisions, licensing, collaborator access and any future public release.

Changes should normally arrive through a focused branch and draft pull request, with a specification where appropriate, tests and review evidence. The maintainer resolves design disagreements after considering alternatives and user impact. Significant machine/serial changes require explicit scope and independent review where available.

No contributor permissions, automatic merge policy or branch-protection guarantee is implied by this document. Repository settings must be verified separately. C2C-owned material uses the MIT License; third-party terms are preserved. Contributors must have rights to their submitted material. Maintainer review, not a file claim or download, controls confirmed-profile status.

## Profile evidence and releases

Unverified starter files belong in `profiles/starters`, not bundled defaults.
Three owner-reported tested setups may be offered in the catalog without automatic installation. A maintainer may promote a profile to independently confirmed status only after
reviewing real-machine evidence from the contributor and a separate tester,
including dates, the exact setup and matching successful operations. Review
must retain failures and limitations. Software simulations do not qualify.
External imports always remain unconfirmed local copies; they cannot award a
public badge or change the catalog. Users can download public files without an
account, but GitHub requires an account to submit an issue or pull request.
